# 공개 준비와 새 설치 검증

## 현재 정리 · 2026-10-21

사용자 요청에 따라 **개발·검증 작업은 완료**로 정리합니다. 실제 브라우저 125%·200% 확대 배율 검증과 자체 코드 라이선스 결정은 이번 완료 범위에서 제외하여 **별도 보류**로 유지합니다. 두 항목을 통과한 것으로 표시하지 않으며, 전체 공개 배포 준비 상태는 `publicReady: false`입니다.

완료 근거는 전체 회귀 **2,086개 통과·실패 0개**(선택적 JDK 검사 1개 제외), 삼성 폴더 없는 새 설치의 공통 회귀 **1,856개 통과·실패 0개**(삼성 관련 검사 32개 제외), 공개 후보 **448개 검사 위반 0개**, 실제 UI 검수 기록입니다. 폰을 변경하는 동작과 실제 변경 효과는 기존 합의대로 시험하지 않았습니다. 아래의 중간 단계 기록은 과거 검증 이력이며 이 절의 최종 상태와 구분합니다.

## 현재 정책

공통 기능은 삼성 확장이 없어도 실행되어야 합니다. 개인 설정·조회 기록·백업·캐시는 로컬에 보존하되 공개 대상에서 제외합니다. 자체 코드의 공개 라이선스는 사용자 결정 전까지 공개 배포의 보류 조건으로 남깁니다.

`package.json`의 `private: true`는 실수로 npm에 게시하지 않도록 유지할 수 있으며, Git 저장소의 공개 여부를 결정하는 항목은 아닙니다.

## 공개 파일 만들기

```powershell
node tools/check-public.mjs
node tools/export-public.mjs --out ..\adb-desk-public
```

내보내기는 원본 프로젝트 밖의 존재하지 않는 새 폴더만 허용합니다. `.local`, `config.json`, `.env`, 백업·실행 기록·캐시·설치된 `node_modules`는 복사하지 않습니다. 구식 연구 문서는 기본 공개 목록에 넣지 않으며, 현재 런타임에 필요한 메뉴 자료와 공개 안내 문서만 포함합니다.

내보낸 `public-export-manifest.json`에는 파일 목록, 크기, SHA-256과 검사 결과가 들어 있습니다. 검사는 확인된 개인 경로·주소·식별자 패턴과 원시 기기 근거가 포함됐는지 확인합니다. 패턴 검사만으로 모든 비밀 정보나 저작권 상태를 증명하지는 않습니다.

Git 저장소에서는 `node tools/check-public.mjs --tracked`로 현재 파일과 Git index의 실제 저장 내용을 따로 확인합니다. 미추적 파일 중 공개 허용 목록 밖의 후보도 보고합니다. 파일명과 공개 JSON 자료도 검사하며, 내보내기는 복사 전 검사에 실패하면 대상 폴더를 만들지 않습니다. Windows 경로 대소문자와 폴더 연결의 실제 위치를 확인하여 원본 안으로 내보내는 경로도 차단합니다.

삼성 확장을 제외한 배포 복사본은 다음처럼 만들 수 있습니다.

```powershell
node tools/export-public.mjs --core-only --out ..\adb-desk-core
```

## 깨끗한 설치 검사

```powershell
node tools/verify-clean-install.mjs
```

검증기는 운영 서버와 별도의 임시 폴더·임시 포트를 사용하며 다음을 수행합니다.

1. 공개 대상 파일만 복사합니다.
2. 복사본에서 `npm ci`로 의존성을 새로 설치합니다.
3. 개인 환경변수·기존 로컬 설정을 사용하지 않고 제조사 확장 비활성 상태로 실제 서버를 시작합니다.
4. 기본 화면과 정적 파일 제공, 확장 상태를 확인합니다.
5. 삼성 확장을 복사본 바깥으로 이동하여 물리적으로 제외한 상태로 다시 시작합니다.
6. 공통 기능 테스트에서 모의 ADB로 파일·앱·설정·로그 등의 동작을 확인합니다.
7. 삼성 폴더가 없는 복사본에서 공통 회귀 테스트 전체를 실행합니다.

실제 ADB 연결을 막는 검증 전용 환경을 사용합니다. 설치 과정은 패키지 다운로드를 위해 네트워크가 필요할 수 있습니다. 검증 결과와 로그는 출력된 임시 폴더에 보존하며, 원본 프로젝트와 개인 데이터를 삭제하지 않습니다.

## 2026-10-21 실제 사이트 UI 검수

기존 인앱 브라우저의 정상 제어 API에서 탭 읽기·새로고침·DOM 조회·화면 캡처가 가능했습니다. URL 접근 제한은 이번 검수에서 재현되지 않았습니다. 당시 세부 정책 원인을 확인할 기록은 없어 차단 원인을 단정하지 않습니다. 보안 정책·권한을 변경하거나 다른 브라우저·별도 제어 수단으로 우회하지 않았습니다.

연결된 기기에서는 조회·목록 선택·탭 이동·팝업 열기와 닫기만 수행했습니다. 폰의 설정·권한·앱·프로필 변경, 재부팅, 미러링 연결 시작, 입력 전송은 수행하지 않았습니다.

- 기기 관리 13개 탭을 실제 화면에서 확인했습니다. 1440·1024·390px 및 좁은 사이드 메뉴 구간에서 가로 넘침·버튼·체크박스·팝업 내부 스크롤을 점검했습니다.
- 확장 설정, 페어링, 파일·폴더 선택, 앱 관리, 앱 정보 조회, 개인정보 상세, 관리 프로필 지원 조회 팝업을 확인했습니다.
- 실제 폴더 접근 제한과 재조회, 빈 로그의 재시도, 앱 정보 조회의 로딩·결과, 상세 정보 닫기 후 초점 복귀를 확인했습니다.
- 초록 표시의 조회 전용 상태와 비활성 변경 버튼, 앱별 GPS의 공유 UID 제한을 확인했습니다. 변경 버튼은 실행하지 않았습니다.
- 웹 서버만 일시 중지하여 한글 오류·재시도 버튼·이전 목록 안내를 확인했고, 재시작 뒤 자동 갱신으로 복구됐습니다. ADB 서버는 중지하지 않았습니다.
